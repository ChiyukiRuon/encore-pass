# Implementation notes

## Overview

The repository was initialized from the supplied v0.1 specification. Next.js App Router hosts the React editor and Node API. Uploaded style images are processed only in the browser. The editor no longer exposes source-ticket import; barcode entry sits behind an independent switch available on all three styles. Otherwise tickets are manual keepsakes. Browser-side OCR, PDF text extraction and candidate extraction were removed together with the Tesseract/PDF.js assets and dependencies; `lib/import/files.ts` remains for editor image handling. The barcode-decoding module and its tests remain for the supplied specification's M3 and are not reachable from the UI.

## Draft model

### Activity presets and optional metadata

`lib/ticket/event-fields.ts` owns the selectable field catalogue, three presets (performance/screening, sports, exhibition/conference), independent event categories, values and active-field projection. New drafts use the performance preset. Legacy drafts without `eventFields` keep their original artist, room, doors and seat fields active and appear as custom; their values are not reclassified automatically. Schema version 1 remains compatible through optional additions (`eventPreset`, `eventType`, `eventFields`, `eventInfo`, `customFields`). Root fields retain their old names. New metadata lives in the bounded, allowlisted `eventInfo` record. Artists use one name per line (at most ten); the organizer is separate from the signing issuer.

Preset changes replace the enabled fields and default category without clearing any stored values. Editing the selection changes the preset to custom. Disabled values remain in IndexedDB and JSON export, but `activeEventTicket` removes them before the browser sends a signing request and again before server pass mapping. Custom text rows have stable UUID keys, independent enabled switches and a ten-row limit. Incomplete rows remain editable; signing validates active URLs (HTTPS without credentials), email, dates, price/currency pairs and completed custom rows. End dates cannot precede start dates. Sports poster signing requires both enabled team abbreviations; an empty optional performer list uses generic semantics.

The front retains event/date/venue/seat hierarchy, using admission level when no seat fields are filled. Complete selected metadata and custom rows are available as back fields and in the collapsible browser details preview. Event-poster passes also carry typed semantics (category, artists, teams, time, admission, price and expanded seat metadata). Supported venue/transport/parking/accessibility contacts map to top-level Apple information links and remote `info_links`; all links, including schedule URLs, remain in back fields for fallback styles. Other layouts keep their existing layout rules and use back fields for extra metadata. Browser preview is approximate and does not reproduce Apple's automatic semantic layout.

`ticketDraftSchema` validates complete business drafts. `exportTicketSchema` additionally requires barcode confirmation when `barcodeEnabled` is true and content exists; turning the switch off hides the code while its format and content stay in the draft. In-progress incomplete drafts are intentionally editable and are automatically saved to IndexedDB. Legacy `posterEventTicket` drafts retain their style and infer the switch from barcode content only when the switch is absent; retained barcodes elsewhere stay hidden until the switch is enabled. `mapPass` emits `barcodes` only when the switch is on, and the API validates and forwards barcodes only then. The editor omits retained content from the request while the switch is off, so it never leaks into a pass. Pass identity always comes from environment configuration and serials are generated on the server.

## Signing modes and layouts

Local signing uses passkit-generator with a validated certificate/key/intermediate pair. `eventTicket` always uses the classic layout, with any active barcode at the bottom. `posterEventTicket` uses the poster layout only with background artwork and an active barcode. `posterGeneric` uses native iOS 27 poster generic only with background artwork (`generic` fallback plus `posterGeneric` fields). Every style uses the classic layout without background artwork. Only poster event passes carry `preferredStyleSchemes: ["posterEventTicket", "eventTicket"]` and semantic event tags. Native generic posters carry four primary fields (event and seat details) and one footer field (venue), with no event semantics; the start time stays on the back and in relevantDate. Preview mode returns 503 unless the editor explicitly opts into Wallet MCP Pass test signing via the X-Encore-Remote-Sign: walletmcppass header. Remote mode also requires that consent header at the API boundary. The adapter sends mapped fields and normalized images to the fixed walletmcppass.com endpoint: the classic layout uses `style: eventTicket` with logo/thumbnail/background @3x; the poster event layout uses `style: eventTicket` + `semantic_layout: true` + semantics with primaryLogo/logo/secondaryLogo/artwork/background @3x. The adapter maps an active barcode's Apple format to the provider name (`QR`, `PDF417`, `Aztec`, `Code128`), sends `barcode_format`, `barcode_message` and `barcode_alt_text` (fixed 仅供展示), and rejects a returned pass whose barcode format or message differs. 通用凭证 uses `style: generic` plus `poster: true`, `footer_fields`, primaryLogo/logo and background @3x when artwork exists; without it, the adapter sends the classic event request with thumbnails. Native generic poster requests never send artwork or secondary logos. It never pays and only resubmits smaller images after an explicit create-endpoint HTTP 413; it bounds responses and archive expansion, checks signature presence and manifest hashes, and returns the pkpass plus a validated one-hour download URL header. It does not verify the Apple trust chain. The provider rebuilds resources with non-scaled PNG filenames, so visual equivalence was checked on a real device. No source tickets are transmitted. See `agent-docs/OPERATIONS.md`.

## Barcode decoding

Barcode decoding is retained but unreachable from the UI. Missing byte payload metadata limits decoded payloads to printable ASCII; QR byte segments are checked against the selected encoding. The retained module always requires separate barcode confirmation. The current editor exposes neither source-ticket import nor a barcode decoder; barcode entry is manually typed behind the switch, and any format or content change resets the confirmation.

## Limits and health

Limits are single-instance budgets, not distributed controls. Production requires ACCESS_PASSWORD unless ALLOW_UNAUTHENTICATED=true. Compose binds localhost by default. Health is public and describes configured mode rather than certificate readiness.

## Verification

Tests use synthetic tickets and ephemeral self-signed certificates. They validate archive content, manifest hashes, and detached signature math, not Apple trust or iPhone installation. Real Wallet installation and Docker execution have been verified. See `agent-docs/VERIFICATION.md` for the suite-by-suite coverage and device checks.

## Editor styles

The editor offers three styles and an independent barcode switch. Classic event tickets keep the same header, blurred background, primary/secondary fields, thumbnail and seat row regardless of barcode visibility; the barcode is anchored 14pt above the bottom without moving other content. Poster event tickets use that classic layout without background artwork or a barcode, and the shared poster layout when both exist. The poster layout has a bare header, sharp artwork, a barcode above the 118pt seat/venue footer and an optional secondary logo for poster event tickets only. The poster event header keeps two lines: the date value above the start time, without the 日期 label, and the time uses the label colour; classic and poster generic headers keep the 日期 label above the date. Without section, row or seat fields the footer's main line falls back to the event name under an 活动 label, so an empty seat row never leaves the band blank. Generic passes use the classic layout without background artwork and native poster generic with it; they always allow thumbnail uploads, displaying and exporting thumbnails (including legacy hero images) only without background artwork. Adding background artwork hides the thumbnail without clearing it; removing the background restores it. Generic passes never show or export secondary logos, and their secondary-logo upload control stays hidden.

## Poster generic preview

The poster generic preview keeps the standard 343x474 card and redraws the native layout from the supplied iPhone screenshot: the shared header (logo, optional logoText, date) over sharp artwork with the usual top scrim, and a 118pt material band. The header date stays at the right edge even without a logo or artist text. The band's top padding is 30pt so the barcode card can overlap it, the four primary fields (event, section, row, seat) share one row, and the bottom line draws the venue without a label; the exported poster footer carries the venue too. Missing seat fields collapse that row: only the trailing column is right-aligned, so a lone event field stays left-aligned. Poster generic labels keep the separate label colour at 12pt; values use 16pt. The shared barcode card sits 109pt above the bottom, is 137pt wide with a 117pt code and a 13pt caption, and overlaps the band by about 9pt; wide formats keep the shared 228pt panel. The poster event and classic layouts use the same card, anchored at the classic bottom or above the poster footer. The band tone samples the artwork above the band (the top 74%) instead of the bottom strip, which matches the darker material in the supplied captures. The preview frame stays 343x474 even though the exported poster background is still 345x505 at 3x.

## Preview behavior

All three styles accept QR, PDF417, AZTEC and CODE128. Switching styles or hiding the barcode retains its content; export and preview include it only when enabled. Poster drafts preserve explicit off switches on reload. The preview scales from a 343x474 pt card via container query units. Classic background blur remains 7pt at scale 1.06, fitted against a real Wallet screenshot. The background keeps its full 343x474 geometry when the card collapses, so collapsing reveals the top of the artwork instead of re-cropping it. The 正常/折叠 toggle transitions the card between 474pt and the 60pt header over 200ms with the sheet's drawer curve while the body fades; the body stays mounted but inert when collapsed. Reduced-motion preferences drop the height movement and keep a 150ms body fade. Browser previews cannot guarantee native Wallet positioning; real-device and Docker verification have been completed.

## Visual theme

The visual theme is ACG-leaning (二次元) and drawn from live concerts. The palette is 晴空樱 (Festival Sky): light/dark tokens in `app/globals.css`, sky blue for interaction, sakura and lemon as accents only. Keep pink off interactive controls so nothing competes with the red destructive colour. The export action uses Apple's black badge styling (white label on black, 8 px corners); `--stage` is the sky (night sky in dark mode) behind the preview. The brand mark 镭射票 is a tilted holographic keepsake ticket with a sparkle: `app/icon.svg` and `BrandMark` in `app/layout.tsx` are two copies that must stay in sync, and `iconSvg` in `lib/wallet/pass-builder.ts` draws its one-colour version as the pass icon. New drafts default to `#1668c7` / `#ffffff` / `#fff3b0`. Text, control, focus-ring, export-label and default pass colour pairs were checked against WCAG AA.

## Appearance pipeline

Appearance uploads are `logoDataUrl`, `thumbnailDataUrl` (shown to users as 角标), `backgroundDataUrl` and `secondaryLogoDataUrl`; all four may coexist. `passImageOutputs` (`lib/ticket/appearance.ts`) maps each upload to Wallet files: logo 160x50 pt (50 pt minimum width, no padding), primaryLogo 126x30 pt for the poster layout, thumbnail 90x90 pt rounded transparent PNG, background 343x503 pt for the classic ticket (345x505 pt for native generic posters), artwork 358x448 pt for Apple's native poster artwork, and secondaryLogo 135x12 pt without cropping for the poster layout. `imageSourceSizes` gives the browser the largest source size (logo 160x50, thumbnail 90x90, background 358x505, secondaryLogo 135x12). Images export at @2x/@3x only; the required icon exports at 1x/2x/3x. The legacy `heroDataUrl` is migrated to the thumbnail on load and treated as a thumbnail on export; strip images are never produced (HIG limits strips to coupons and store cards). `backgroundMaskOpacity` (0–1, default 0) applies to the blurred classic layout and darkens its background image before export; the black overlay is composited onto both `background.png` and `artwork.png` at every scale, so local and remote signing receive the same masked pixels. The mask control shows for `eventTicket` with background artwork and for `posterEventTicket` in its classic fallback (background artwork without an active barcode). Poster event poster layouts and generic passes ignore retained mask values in previews and exports. Returning to a classic layout restores the saved mask value. The style section no longer estimates text contrast.

## Image crop picker

Every upload opens a region picker before it changes the draft. The picker shows the original upload (bounded to 2 MB and 16 megapixels) and a draggable, resizable frame; thumbnail locks 1:1, background locks 343:503 on the classic layout, 358:448 on the poster event layout or 345:505 on the generic poster layout (decided by style and active barcode, not by whether the new background exists yet), and logo/secondaryLogo stay free so they keep the fitted `inside` behaviour. The initial selection is the largest centred region for locked frames and the whole image otherwise, reproducing the previous automatic crop. Confirming crops the original before sizing the selection for @3x output, using lossless PNG for every slot; a full-image selection retains the original bytes; crop geometry and the picker's pointer/keyboard handling live in `lib/ticket/crop.ts` and `components/editor/image-crop-dialog.tsx`. A non-full selection also stores the original source in `appearance.imageSources` and the normalized rectangle in `appearance.imageCrops`; the「调整」action reopens the picker from that source. Old drafts without a source use the current slot image, and resetting a free slot to the whole image deletes both extra records. The server ignores these fields and the editor strips them from `POST /api/passes`, so signing payloads stay at one image per slot; the local draft and exported JSON keep them for re-editing, which raised the JSON import bound to 32 MB.

## Venue timezone

The venue timezone control is a grouped native select over the engine's full IANA list (`Intl.supportedValuesOf('timeZone')`), with UTC added because some engines omit it and a short fallback list for browsers without `supportedValuesOf`; a stored alias that the list omits is offered as an extra option. New drafts start on the device zone (`Intl.DateTimeFormat().resolvedOptions().timeZone`) and fall back to `Asia/Shanghai` when the resolved zone is invalid, while loaded drafts keep their saved zone.

## Save, export and consent UI

The save section automatically persists browser drafts with a 400 ms debounce, without a save toggle or routine status. Import and clear are icon-only actions at the right of the event-information section heading; the save section keeps only the export action, status and error text, plus a question-mark help action at the far right of its heading. That action opens an iOS-style sheet over a dimmed, slightly blurred backdrop: on wide screens it scales and fades in at the centre, on narrow screens it slides up as a bottom sheet with 20 px top corners; dismissal reverses the presentation (220 ms) before the native `<dialog>` closes. The sheet documents both save paths, iPhone installation, privacy and the entry-credential limits. Escape, the backdrop, the close button and the footer action dismiss it; focus returns to the trigger, background scrolling is locked, and reduced-motion preferences collapse the animation. The root reserves a stable scrollbar gutter so hiding the scrollbar for the lock does not shift the page. Clear all data first opens a confirmation built from the save guide's sheet (same header, footer and 0.38 s/0.22 s animations, same backdrop and mobile bottom-sheet behaviour) with a close button, a cancel action and a destructive footer action; Escape, the backdrop, cancel and close opt out, and the deletion runs only after the sheet closes with confirmation. JSON import replacement uses the same sheet with its own title, copy and confirm label. Clear all data cancels pending saves, drains writes and clears the draft store before resetting the editor, consent and download link. Only storage errors are surfaced. Without signing consent, export downloads the editable TicketDraft as ticket.encore.json entirely in the browser, including incomplete fields, retained barcodes and images. JSON import is bounded to 32 MB, migrated and validated with editableDraftSchema before replacing the editor after confirmation. Signing consent is never persisted or imported. Turning the signing switch on opens the shared confirmation sheet with short copy and a tinted primary confirm action; the sheet has no timer, and cancel, Escape, the backdrop or close leave the switch off until the confirm action is chosen. The standing JSON-export note under the button is gone. The signing switch uses the standard switch styling; an active barcode also requires an explicit confirmation switch. Safari on Apple platforms is detected heuristically for the supplied Chinese Apple Wallet badge. Its action signs and navigates to the validated provider download URL; other browsers download ticket.pkpass. Device detection is not proof of native installation support. Browser tests mock signing; native Wallet installation and Docker have been verified.

## Remote REST contract

REST integration follows the live provider schema reviewed at https://walletmcppass.com/llms-full.txt and the upstream server.py/pass_builder.py/semantics.py. Poster event API requests always include venueName, venueRegionName and venueRoom strings; absent values remain empty rather than invented. The draft exposes optional region/room fields, and uses generic eventType when performerNames is unavailable. The API hardcodes Latin-1 barcode encoding with no override: remote signing rejects non-ASCII UTF-8 payloads before network use; local signing retains the draft encoding. Returned layout flags, optional serial/issuer metadata, barcode content and manifest completeness are checked before exposing the download link. HTTP 400 is a safe validation error, 402/429 is quota exhaustion, and 503 is provider capacity. Only create-endpoint HTTP 413 permits compressed resubmission; no other retries or payments. Live REST smoke with synthetic fixtures and real-device installation completed; mocked contract coverage includes every style/background/barcode combination. Browser tests use current consent/about wording and retain the existing user confirmation flow.

## Remote error staging and proxy

Remote signing errors are stage-specific: request transport, provider response, download, archive validation, layout, barcode and identity. Only allowlisted transport codes are returned; raw upstream errors and payloads remain private. Standard proxy environment variables require Node's startup opt-in (NODE_USE_ENV_PROXY=1 on supported Node releases); no global or project proxy settings are changed automatically. Historical EACCES failures in an agent environment do not establish the cause of a user's running server failure.

## Remote payload budget

Remote signing sends original @3x resources first, with no guessed outbound request-size cap. Only an HTTP 413 from the create endpoint advances a lazy compression sequence: lossless PNG optimization, 256 colours at full resolution, 128 colours at full resolution, then 128 colours at @2x for artwork/background. Every attempt starts from the original buffer; only strictly smaller serialized bodies are sent. Logos, icons and thumbnails stay lossless. At most four alternatives follow the original request, all within the same 15-second deadline. Exhausted alternatives map to REMOTE_PAYLOAD_TOO_LARGE. Network errors, other HTTP statuses, downloads and validation failures never retry; payments remain disabled.
